# Epic-01 로컬 개인화 Prototype 통합

Jira: https://lumira077.atlassian.net/browse/KR1-1

Python 3.11 이상. 저장소 루트에서 `python Epic-01/integration/run.py`.
표준 라이브러리와 기존 F2002 S01·S02를 사용한다. GitHub Actions는 동일 명령으로 테스트하고 소스 커밋 SHA가 담긴 report.json을 Artifact로 보존한다.

각 Feature의 S01은 설계 계약, S02는 핵심 로직, S03은 시뮬레이션 시험, S04는 운영 지표·출시 판단 초안이다. S03·S04의 실기 통합·실사용·Release 완료조건을 충족한 것으로 간주하지 않는다.

## 중요한 경계

- Context epoch와 가상 ACK는 개발 프로세스 내부 계약이다. 분산 모듈에 안전성을 보장하지 않는다. 실제 소비자가 취소 ACK와 epoch를 재검사해야 한다.
- FamilySession의 owner는 신뢰된 호출자가 제공하는 값이다. 실제 인증·가족 구성원별 접근 범위는 구현되지 않았다. 로컬 샘플의 confirmed/administrator/guardian 인자는 실제 권한 검증 증거가 아니다.
- 사용자 삭제·프로필 변경은 다음 `FamilySession.read`에서 검사한다. 실행 전 각 소비자는 최신 read를 수행해야 한다. 이미 외부로 나간 출력/캐시의 취소·회수는 미구현이다. 애플리케이션 실패 시 장치를 disconnected로 두며 실기 연결상태 관리와 분리해야 한다.
- Model Policy의 음량40/동작1은 예시 소프트웨어 제한이다. 기종·의상별 실측 승인값으로 대체해야 한다.
- Theme의 3초 presence TTL은 가상 이벤트 시계 기준이다. 실물 태그의 상시 감지·제거 확인 방식은 하드웨어 결정이 필요하다. UID 복제 검출·인증을 제공하지 않는다.
- 기억·생체·원문·클라우드 동의는 모드나 테마 전환으로 추가되지 않는다. 관심사·알림 선호 필드는 F2002 현재 Prototype에 없으므로 별도 스키마 확장·데이터 마이그레이션이 필요하다.
- release_ready는 항상 false. 실사용 참가자는 0명. 운영키·실물·LLM·승인 시스템이 미연결이다.

## 개입 필요

1. 실제 로봇 기종, ROS/출력 API, 기종·의상별 안전 제한과 장비 접근 제공.
2. SKU별 기능·콘텐츠·모드·연령·보호자 권한표 확정; 사업 문서의 다른 모델명 매핑 승인.
3. NFC reader·태그·제거/presence 센서 결정 및 승인 의상/에셋 제공.
4. 실제 AI/음성 모델·서비스, 인증·배포/패키지 서명 구성 제공(비밀값은 저장소/Jira에 입력하지 않고 Secret 설정 사용).
5. 실제 평가 대상·성능 목표·Q1/R1 검토 담당과 승인 방법 확정.
6. KR1-1 종료일 2028-02-29와 KR1-37 종료일 2028-10-31 불일치 조정.
