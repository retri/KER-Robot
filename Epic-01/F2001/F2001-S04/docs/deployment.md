# 배포·복귀 및 증적 승인

## 배포 전

후보 commit/version, S02/S03 파일 해시, 펌웨어·로봇 기종·제어 모델·스키마·설정·대화 자산 버전을 manifest에 고정한다. 의존성 해시 변경은 중단하고 검토된 manifest와 회귀 시험으로 갱신한다. 실제 장치 호환성과 스키마 마이그레이션·복귀 가능성을 검토한다. 사용자 연구 재시험·실기 S03·운영 기준·blocker 결함 0·Q1/R1의 해당 증적 승인을 확보한다.

`release.evaluate(bundle, approvals, trusted_keys)`는 증적 digest에 결합된 Q1/R1 HMAC 승인을 검사한다. 승인 키는 권한 있는 검토 채널에서 제공해야 하며 이 도구의 자체 키 생성은 승인 권한이 아니다. 검토자의 신원 검증·키 관리·서명 전달 및 원본 증적의 진위 검증은 조직 시스템에 연결해야 한다. 기본 Demo에는 서명이 없다. 실제 release 실행/자동 배포 기능은 없다.

## 운영 배포 절차(아직 미수행)

1. 승인된 패키지와 manifest, 백업·최신 삭제/철회 원장·복구 키를 별도 보호 저장소에 확보한다.
2. 서비스 입력·출력을 일관된 안전 상태로 중지하고 SQLite 단일 작성자 가정 또는 실제 DB 잠금·트랜잭션 프로토콜을 검증한다.
3. 검증 환경에 마이그레이션·배포를 적용하고 기존 프로필과 진행 세션 보존, 정책 동의, 권한, 취소·재개·중복 방지·안전 출력을 검사한다.
4. 제한 배포 후 실측 지표·누락·오류·사용자 영향 확인, 담당자 승인 후 확대한다. 버전/시간/기종/증적/담당자 기록.
5. 실패 시 확대 중단, 승인된 복귀 절차 후 데이터 보존·최신 철회·실기 재확인. 스키마가 비호환이면 코드만 되돌리지 않는다.

## 개발용 복원 시험

`RestoreLab`은 `.ker-development-sandbox` 표식과 알려진 파일명만 허용하며 심볼릭 링크를 거부한다. 스키마 2만 지원한다. SQLite backup API로 snapshot을 만들고 최신 별도 `privacy-ledger.json`을 메모리에 재적용한 뒤 sandbox DB에 저장한다. 삭제 프로필·세션 내용·관련 적용/완료/ACK를 제거하고 철회는 프로필·동의 이벤트·세션·적용 context에 반영한다. 철회 후 적용 상태는 pending으로 바꾸고 이전 ACK를 제거한다. 진행 중 등록은 보존한다. 원장 미확보·순서 오류·비호환 스키마는 거부한다.

원장 전체성·최신성·권한·서명·암호화·실제 백업 보존과 외부 로그/캐시/장치의 삭제는 개발 시험의 범위 밖이다. 실제 운영에서는 서비스 정지/출력 차단, 잠금, 감사, 원장 진위, 저장 공간, 복구 시간·시점 목표를 검증해야 한다. 본 시험 결과는 `scope=development_sandbox`, `production_restore_verified=false`다.
