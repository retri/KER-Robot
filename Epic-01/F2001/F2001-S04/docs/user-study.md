# 사용자 검증 계획·기록·재시험

현재 상태: 실제 사용자 연구 미수행. `study-simulated.json`은 데이터 형식 예시이며 참가자 증적이 아니다.

1. 연구 담당자는 목적, 동의·철회 방법, 최소 수집·보존 기간, 접근권한, 도움 요청·중단 절차를 승인받는다. 참가자 연락처·동의서는 별도 보호 저장소에 보관하고 프로그램에는 무작위 32자리 가명만 전달한다.
2. 고령자·보호자를 포함한 실제 참가자 최소 10명을 모집한다. 동일 후보 버전의 정상 연결 기본 등록 재시험 최소 10건을 확보한다. 이는 프로그램에서 강제하는 초기 제안 기준이며 담당 검토자가 적절성을 확정해야 한다.
3. 기본 등록, 보호자 등록, 게스트 이용, 중단 후 재개, 연결 끊김, 설정 변경을 평가한다. 전체 연구에서 6개 시나리오가 모두 포함되어야 한다. 고령자·보호자의 접근성, 음량·속도·문구 이해, 오류 회복과 도움 요청을 관찰한다.
4. `baseline`에서 문제를 발견하고 별도 결함 기록에 가명·시나리오·재현 조건·영향·수정 커밋·증적 위치를 연결한다. 수정 후보 버전에서 `retest`를 수집한다. 같은 참가자/과업/단계/버전 중복은 거부한다. 새 재시험 라운드는 새 후보 버전 또는 명시적 기록 모델 확장 후 사용한다.
5. 독립 수행은 도움 없이 완료하고 300초 이하인 정상 연결 기본 등록이다. 재시험 성공률 80% 이상, 최소 참가자·과업·대표집단 조건을 함께 확인한다. 장비 장애 시 정상 연결 분모에서 제외해도 장애 시나리오 증적과 실패 사유는 따로 남긴다.
6. `evaluate_users(records)`에 실제 기록을 넣고 결과·원본 관찰 증적·방법론·결함 조치·재시험을 검토자에게 제공한다. `observed` 표시는 출처 라벨이며 실사용 증명이 아니다. Q1/R1 승인과 하드웨어·운영 증적이 추가로 필요하다.

JSON 기록 필드: participant_id, group(general/elderly/guardian), task(basic_registration/guardian/guest/resume/connection_loss/settings_change), phase(baseline/retest), mode(simulated/observed), completed(bool), assisted(bool), seconds(0..86400), normal_connection(bool), version(semver). 이름·연락처·음성 원문·전체 동의서는 금지한다.

승인 및 관찰 증적 위치, 연구 날짜·담당자, 참가자 선정 편향과 한계는 보호된 연구 보고서에 기록한다. 이 도구는 보고서 진위나 연구 윤리를 자동 검증하지 않는다.
