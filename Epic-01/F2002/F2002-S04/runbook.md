# 운영·배포·복귀·사용 안내

## 사용 안내

본인 프로필을 선택하고 현재 설정을 확인한 뒤 변경 내용을 저장한다. 다른 수정이 먼저 반영되면 최신 값을 다시 조회하고 재검토한다. 동일 요청 재전송에는 동일 mutation_id를 사용하며 다른 변경은 새 키를 사용한다. 기본값 복원은 선택 동의를 변경하지 않는다. 로봇 프로필 전환 후 전체 모듈 적용 상태를 확인한다. 저장 완료는 실제 로봇 이용 준비를 의미하지 않는다. 오류·단절 시 새 활성화를 요청하고 반복 실패는 담당자에게 허용된 오류 코드로 전달한다.

## 운영 대응

모듈 적용 실패는 저장 프로필을 유지하고 실패 모듈·ACK를 조사한다. 동일 적용 재시도는 완료 모듈을 건너뛰고, 프로필 수정/전환 이후에는 새로운 application을 생성한다. stale 요청은 자동 재사용하지 않는다. 동의 철회/삭제 시 원본·모든 서비스·장치 캐시·백업 복원·F2001 source의 반영을 확인해야 하며 현재 Prototype은 S02 DB와 새 적용 요청의 차단까지만 제공한다. 운영 privacy 전달 미연결 상태로 실제 배포하지 않는다.

로그는 stamp·허용된 연산 kind·오류/모듈 code만 저장한다. 토큰/URL/body는 HTTP 로그에 쓰지 않는다. 로그 보존·암호화·접근·감사와 경보 임계치는 승인 대상이다. 실패율 분모는 apply_attempt 연산 횟수이며 미인증 요청·충돌·유실을 모두 포함하는 관측 체계는 아니다. 실제 운영 mode·버전·장치별 지표는 추가 통합해야 한다.

## 배포 절차(미수행)

후보 SHA/계약·DB 스키마·펌웨어/기종·자산·설정을 manifest에 고정한다. 전체 소프트웨어 회귀, 실제 로봇 안전·사용자 연구·운영 기준·blocker 0·Q1/R1 승인과 개인정보 동기화 연결을 확인한다. 승인된 백업/최신 삭제·철회 원장을 확보하고 입력/출력을 안전 상태로 정지한다. 검증 환경 마이그레이션·복귀를 먼저 수행하고 기존 데이터·진행 세션/바인딩 상태를 검사한다. 제한 배포 후 지표·오류·안전 상태를 확인해 확대한다. 실제 실행 도구는 없다.

## sandbox 복원

RestoreLab은 표식 디렉터리의 고정 파일명만 허용하고 symlink를 거부한다. 스키마 1만 지원하며 비호환 복귀는 차단한다. SQLite backup snapshot에 최신 별도 원장의 delete/revoke를 재적용한다. 삭제는 프로필/요청/적용 제거, import tombstone; 철회는 consent false와 revision 증가; 모든 ACK와 active 바인딩을 폐기하고 재활성화를 요구한다. 복원 DB는 개발 sandbox에만 저장한다.

최신 원장 진위·완전성·암호화·실제 백업·외부 캐시/F2001 원본 삭제·서비스 잠금·출력 정지·RTO/RPO·담당자 서명은 구현하지 않았다. 실제 운영 복귀 시험은 별도 필요하며 code-only rollback으로 스키마를 되돌리지 않는다.
