# 운영·사용 안내·배포·복귀·Release notes

## 사용자 안내

장기 기억 동의와 클라우드 전송 동의는 별도다. 기억해 달라고 말하면 후보를 확인하고 저장을 확정한다. 후보는 확인 전 회상에 사용하지 않는다. 자신의 기억을 조회·정정·삭제할 수 있으며 동의 철회 시 저장 기억을 제거한다. 재동의는 옛 기억을 복원하지 않는다. 잘못된 회상은 정정/삭제 후 다시 확인하고 반복되면 담당자에게 오류 코드만 전달한다. 원문 대화 저장 동의가 꺼져도 동의한 추출 기억은 별도 목적에 따라 저장될 수 있음을 안내한다.

## 운영 대응

검색/모델/인덱스 장애에는 빈 기억으로 fallback하고 확인되지 않은 회상을 만들지 않는다. 권한·동의 오류에는 다른 사용자의 기억으로 대체하지 않는다. 잘못된 회상은 source/version·정정 이력·검색 설정을 보호된 증적으로 검토한다. 이름·기억·검색어·대화·token을 로그/Jira에 남기지 않는다. 소프트웨어 로그는 시간·버전·허용 연산 kind/code만 저장하며 모든 요청/오류/누락을 관측하는 중앙 로그는 아니다. 보존·접근·암호화·경보·SLO·담당자 연락망은 미승인.

동의/프로필 변경은 F2003 synchronize 또는 명시적 revoke/grant 경로로 전달한다. F2002에서 off/on을 F2003 관측 없이 처리하면 누락될 수 있으므로 운영에서는 단일 권위 consent epoch/보호된 이벤트를 연결해야 한다. 이미 응답받은 호출자·외부캐시·사용자별 클라우드 복제·백업까지 삭제 책임을 확정한다. SQLite 물리 완전 소거와 암호화는 미구현.

## 배포 전(아직 미수행)

소스·규칙/모델·프롬프트·검색/임베딩·계약·스키마·기종·펌웨어·설정을 고정한다. dependencies는 코드 해시 검출용이며 승인자의 신원·패키지 서명을 보장하지 않는다. build_dependencies는 승인된 변경 검토 후에만 사용하고 CI에서 임의 재생성하지 않는다. 실제 인증/키/보존·동의 이벤트, 모델 품질·누출/공격, 로봇/사용자/운영·복귀·blocker0·Q1/R1 승인 필요. Release 평가기는 승인 시스템이 연결되지 않아 항상 blocked이며 배포를 실행하지 않는다.

## 개발 복원

출력/입력을 안전하게 정지하는 실제 절차와 DB잠금은 운영에서 별도 검증한다. 개발 RestoreLab.backup→현재 privacy 원장 export_latest_ledger→restore 순서로 수행한다. 외부 파일은 backup과 별도 보관하고 실제 최신성·완전성·진위 확인이 필요하다. snapshot 원장의 전체 prefix와 최신 원장 prefix를 비교해 누락/변조를 차단하되 snapshot 이후 최신 기록 누락 자체는 인증된 head가 없어 완전히 탐지할 수 없다.

새 delete/expire/supersede/correct는 오래된 원본·인덱스를 제거하고 retired request token을 재적용한다. delete_all/revoke/profile_deleted는 scope 기억을 제거, revoke/profile_deleted는 재사용 차단; 명시적 grant만 차단 해제. snapshot 이전 원장을 다시 재적용하지 않아 backup에 이미 반영된 새 기억을 불필요하게 삭제하지 않는다. 현재 만료 정보와 모든 context ticket도 제거한다. 최신 원장만으로 backup 이후 생성/정정 내용까지 재구성하지 않는다. RPO·감사·실제 복제 상태를 검토해야 한다.

스키마1만 복원하며 비호환 code-only rollback은 차단한다. 기종/모델/임베딩 변경에는 승인된 마이그레이션·인덱스 재구성·품질 재평가가 필요하다. 결과 scope:development_sandbox, production_restore_verified:false.
